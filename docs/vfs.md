# linur — the VFS with paths (M2.2, updated at M2.5)

Status: interface contract for M2.2, updated by M2.3, M2.4 and M2.5.
`docs/perm.md` is the M2.3 contract, `docs/block.md` the M2.4 one and
`docs/elf.md` the M2.5 one (own ELF parser, `envp`, `#!` scripts). Read with
`spec/02` (M2.2–M2.5), `spec/01` §4/§5, `docs/errors.md` and `docs/reland.md`.
M2.2 replaces the single-name lookup over one global inode with superblock, dentry
and inode objects, a path walker, a per-process cwd, the directory operations,
Linux open flags, fd `CLOEXEC`, and `stat`/`fstat`/`lseek`/hard links
(link/unlink/nlink moved here from M2.1).

## 1. Scope

In: superblock / dentry / inode objects; the path walker with `.` and `..`; cwd,
`chdir`, `getcwd`; `mkdir`, `rmdir`, `unlink`, `link`, `rename`, `readdir`;
Linux-exact `open` flags; fd semantics including `CLOEXEC`; `stat`, `fstat`,
`lseek`; hard-link counts (`nlink`) on disk. M2.3 adds the inode metadata
(`mode`/`uid`/`gid`, device number), the permission checks,
`chmod`/`chown`/`umask`/`access`/`mknod`, a mount table holding one filesystem
and the `/dev` skeleton. M2.4 adds the block layer below all of it: our own
virtio-blk driver and the hash-queue buffer cache with delayed write. M2.5 adds the
own ELF loader behind `exec`/`execve`, with `envp` and `#!` scripts
(`docs/elf.md`).

Out: `mount()`/`umount()` and `chroot` (M6.1); the device table and the real
devices (M3.1/M6.2); timestamps (M3.5); symlinks (DEFER); pipe SIGPIPE (M6.2); a
dentry cache (not scheduled); PIE/ASLR and `PT_INTERP` images (out of scope,
`docs/elf.md` §1).

## 2. On-disk format v3 (easy-fs)

The image is regenerated by every build and the host test recreates its own; there is
no compatibility with the previous format. v3 is v2 plus ownership and the file type
moved into `mode` (`docs/perm.md` §3).

* **Disk inode, exactly 128 bytes** (`repr(C)`), four per 512-byte block with no
  waste: `size: u32`, `nlink: u32`, `mode: u16`, `uid: u16`, `gid: u16`,
  `_reserved: u16`, `direct: [u32; 26]`, `indirect1: u32`, `indirect2: u32`.
  4+4+2+2+2+2+104+4+4 = 128. The 4-byte `DiskInodeType` is replaced by
  `mode`, `uid`, `gid` and `_reserved` (8 bytes), so the direct count drops
  from 27 to 26 to keep the inode at 128 bytes; the maximum file size becomes
  (26 + 128 + 16384) × 512 B ≈ 8.1 MiB.
* **`mode`** holds the `S_IFMT` type plus the `0o7777` permission bits, so
  `DiskInodeType` disappears and `is_dir`/`is_file` read `mode & S_IFMT`:
  `S_IFDIR` 0o040000, `S_IFREG` 0o100000, `S_IFCHR` 0o020000, `S_IFBLK` 0o060000,
  `S_IFIFO` 0o010000, `S_IFMT` 0o170000. `uid` and `gid` are 16-bit on disk and
  widened to `u32` by `stat`.
* **Device number.** For `S_IFCHR` and `S_IFBLK` inodes, `direct[0]` holds
  `dev = (major << 8) | minor` and the inode never allocates a data block;
  `create_node` is the only creator that sets it. `dev()` returns 0 for every other
  type, so a regular file's first data block is never misread as one.
* **`nlink`**: a regular file starts at 1. A directory starts at 2 — its own `.`
  entry and the entry that names it in its parent — plus one per subdirectory
  (each subdirectory's `..` names it). The root starts at 2 (`.` and `..` both
  name the root) plus its subdirectories. An inode (and its data blocks) is
  freed exactly when `nlink` reaches 0.
* **Directory data**: 32-byte entries, 27-byte name plus NUL padding and a `u32`
  inode number. `.` and `..` are real entries in every directory, the root
  included (`..` of the root names the root). A directory is the empty only when
  it holds nothing except `.` and `..`.
* Names: one component is 1–27 bytes, a whole path is at most 4096 bytes.
* `EasyFileSystem::create` must write the root's `.` and `..` entries and own the
  root as `S_IFDIR | 0o755`, uid 0, gid 0.

## 3. easy-fs API (the disk layer)

`fs/src/vfs.rs` (the crate's repository, mounted at `fs/`) exposes these; the crate stays `no_std`, dependency-free of
kernel errno, and returns its own error enum so the kernel owns the errno policy:

```rust
/// Why a directory or inode operation was refused.
pub enum VfsError { NotFound, Exists, NotEmpty, NotDirectory, IsDirectory, InvalidName }

/// One directory entry produced by iteration.
pub struct Dirent {
    pub name: String,
    pub inode_id: u32,
    pub is_dir: bool,
    /// Byte offset to pass to the next `dirent_at` call.
    pub next_offset: usize,
}

impl Inode {
    pub fn inode_id(&self) -> u32;
    pub fn is_dir(&self) -> bool;
    pub fn is_file(&self) -> bool;
    pub fn size(&self) -> u32;
    pub fn nlink(&self) -> u32;
    pub fn mode(&self) -> u16;
    pub fn uid(&self) -> u16;
    pub fn gid(&self) -> u16;
    pub fn dev(&self) -> u32;
    pub fn set_mode(&self, mode: u16);
    pub fn set_owner(&self, uid: u16, gid: u16);
    pub fn read_at(&self, offset: usize, buf: &mut [u8]) -> usize;
    pub fn write_at(&self, offset: usize, buf: &[u8]) -> usize;  // grows eagerly
    pub fn truncate(&self);                                      // frees the data blocks
    pub fn find(&self, name: &str) -> Option<Arc<Inode>>;
    pub fn create_file(&self, name: &str, mode: u16, uid: u16, gid: u16) -> Result<Arc<Inode>, VfsError>;
    pub fn create_dir(&self, name: &str, mode: u16, uid: u16, gid: u16) -> Result<Arc<Inode>, VfsError>;
    pub fn create_node(&self, name: &str, mode: u16, uid: u16, gid: u16, dev: u32) -> Result<Arc<Inode>, VfsError>;
    pub fn remove(&self, name: &str) -> Result<(), VfsError>;
    pub fn link(&self, name: &str, target: &Arc<Inode>) -> Result<(), VfsError>;
    pub fn rename(&self, old: &str, new_dir: &Arc<Inode>, new: &str) -> Result<(), VfsError>;
    pub fn dirent_at(&self, offset: usize) -> Option<Dirent>;
}
```

Rules these methods must keep:

* `create_dir` writes `.` (to itself) and `..` (to `self`) and increments
  `self.nlink`; `create_file` starts `nlink` at 1. `create_file` adds `S_IFREG`
  and `create_dir` adds `S_IFDIR`; `create_node` stores `mode` as given and the
  kernel validates its type before calling. All three reject a name that is
  empty, longer than 27 bytes, or already present (`Exists`) and a non-directory
  receiver (`NotDirectory`).
* `set_mode` writes the whole word and `set_owner` both halves; the kernel passes
  `(old_mode & S_IFMT) | perms` so `chmod` keeps the type.
* `remove` refuses `.`/`..` (`InvalidName`), a missing name (`NotFound`), a
  directory that is not empty (`NotEmpty`), and a non-directory receiver
  (`NotDirectory`). A directory removal frees its `.`/`..` data, its inode, and
  decrements the parent's `nlink`.
* `link` rejects a directory target (`IsDirectory`), an existing name (`Exists`),
  invalid names, and a non-directory receiver; it increments the target's `nlink`.
* `rename` moves `old` from `self` to `new_dir`/`new`: missing `old`
  (`NotFound`), invalid names (`InvalidName`), a file target that exists is
  replaced, a directory target that exists is `NotEmpty` (M2.2 does not replace
  an empty target directory the way Linux does), and a directory moved into its
  own subtree (walk `new_dir`'s `..` chain) is `InvalidName`. Renaming a name onto
  another hard link of the same inode succeeds and changes nothing. Moving a
  directory rewrites its `..` entry and adjusts both parents' `nlink`.
* Removing directory entries returns the data blocks the smaller size no longer
  covers to the bitmap (`DiskInode::shrink_size`, called by `remove` and
  `rename`), so a directory's `size` and its block count move together in both
  directions. This closes the M2.2 limitation (`docs/block.md` §8).
* `truncate` frees the data blocks and sets size 0.
* Filesystem mutators do not flush: a dirty cache reaches the device when it is
  evicted or when `block_cache_sync_all()` runs — the flush the M6.1 `sync` call
  will use (`docs/block.md` §7).
* The old `create(name)`, `ls()`, `clear()`, `link/unlink(name)` and `nlink()`
  root-only helpers are replaced by the API above; nothing outside easy-fs may
  call them afterwards.
* The packing tool creates every app as `S_IFREG` with `0o755` and then the
  `/dev` skeleton of `docs/perm.md` §9 through the same API.

## 4. Kernel objects and API

`os/src/fs/vfs.rs` (new) defines the kernel side:

```rust
/// One name-to-inode binding, as produced by the path walker.
pub struct Dentry { name: String, inode: Arc<Inode> }
impl Dentry {
    pub fn name(&self) -> &str;
    pub fn inode(&self) -> &Arc<Inode>;
}

/// Kernel inode: the disk inode plus the operations the syscalls need.
pub struct Inode { inner: Arc<easy_fs::Inode> }
impl Inode {
    pub fn mode(&self) -> u32;
    pub fn uid(&self) -> u32;
    pub fn gid(&self) -> u32;
    pub fn dev(&self) -> u32;
    pub fn set_mode(&self, mode: u32);
    pub fn set_owner(&self, uid: u32, gid: u32);
    /// Create a regular file; `perms` are permission bits, the type is added here.
    pub fn create_file(&self, name: &str, perms: u32, cred: Cred) -> Result<Arc<Inode>, isize>;
    /// Create a directory; `perms` are permission bits, the type is added here.
    pub fn create_dir(&self, name: &str, perms: u32, cred: Cred) -> Result<Arc<Inode>, isize>;
    /// Create a special file; `mode` carries the type.
    pub fn create_node(&self, name: &str, mode: u32, cred: Cred, dev: u32) -> Result<Arc<Inode>, isize>;
}

/// Resolve `path` against `cwd`; the final component must exist.
pub fn lookup(cwd: &Arc<Dentry>, path: &str, cred: Cred) -> Result<Arc<Dentry>, isize>;
/// Resolve the parent directory of `path` and the final component name.
pub fn lookup_parent(cwd: &Arc<Dentry>, path: &str, cred: Cred) -> Result<(Arc<Dentry>, String), isize>;
/// Open `path` with Linux flags; the file keeps its own offset.
pub fn open(cwd: &Arc<Dentry>, path: &str, flags: OpenFlags, mode: u32, cred: Cred) -> Result<Arc<OSInode>, isize>;
/// Absolute path of a directory, for getcwd.
pub fn absolute_path(dentry: &Arc<Dentry>) -> Result<String, isize>;
/// Whole-file read, for exec and spawn.
pub fn read_all(inode: &Arc<Inode>) -> Vec<u8>;
/// The Linux riscv64 struct stat of an inode.
pub fn stat(inode: &Arc<Inode>) -> Stat;
```

`Inode` delegates to `easy_fs::Inode` and adds `is_dir`, `is_file`, `size`,
`nlink`, `read_at`, `write_at`, `truncate`, `inode_id`, the metadata accessors
(the `u32` user-visible mode, uid, gid and device number), plus the directory
operations (`create_file`, `create_dir`, `create_node`, `remove`, `link`,
`rename`) mapped to errno. `OpenFlags` keeps its name but takes the Linux values of
§7. `root()` and `dev()` move to `os/src/fs/mount.rs`, whose mount table holds one
filesystem; `vfs::root()` and the `SUPER_BLOCK` lazy-static are gone, and `stat`'s
`st_dev` is the mount's device number (`docs/perm.md` §5).

Path rules: a path is absolute when it starts with `/` (it starts at the root),
otherwise relative to `cwd`; repeated `/` are ignored; `.` and `..` resolve
through the real entries; a trailing `/` names a directory and fails with
`ENOTDIR` otherwise; an empty path is `ENOENT`; a component longer than 27 bytes
or a path longer than 4096 bytes is `ENAMETOOLONG`; a component that is not a
directory is `ENOTDIR`; a missing component is `ENOENT`. Each directory the walker
descends into, and the final target of `chdir`, is checked for `MAY_EXEC`
(`docs/perm.md` §6), which is why every path-taking call passes the caller's
`Cred`.

`absolute_path` builds the path by walking `..` from the dentry's inode to the
root and naming each directory from its parent's entries (the inode-based walk
stays correct when the directory was reached through `..`).

## 5. File layer, fd table and CLOEXEC

The `File` trait gains the operations the new calls need; errors become
explicit:

```rust
pub trait File: Send + Sync {
    fn readable(&self) -> bool;
    fn writable(&self) -> bool;
    fn read(&self, buf: UserBuffer) -> Result<usize, isize>;
    fn write(&self, buf: UserBuffer) -> Result<usize, isize>;
    fn lseek(&self, offset: isize, whence: u32) -> Result<usize, isize> { Err(ESPIPE) }
    fn getdents(&self, buf: UserBuffer) -> Result<usize, isize> { Err(ENOTDIR) }
    fn stat(&self) -> Result<Stat, isize>;
}
```

* `OSInode` keeps the per-open-file offset, the readable/writable bits, an
  `append` bit, and the inode. `read`/`write` on a directory return `EISDIR`.
  `lseek` supports `SEEK_SET` 0, `SEEK_CUR` 1 and `SEEK_END` 2; a negative
  result or an unknown whence is `EINVAL`; the returned offset is `usize`.
  `getdents` serialises `linux_dirent64` entries (§9) from the inode's current
  directory offset; a non-directory is `ENOTDIR`.
* A special file (`S_IFCHR`, `S_IFBLK`, `S_IFIFO`) opens with `ENXIO`: there is
  no device table until M3.1 and no pipe file until M6.2 (`docs/perm.md` §5).
* `Stdin`/`Stdout` report a character device and `Pipe` a FIFO in `stat`; both
  keep `ESPIPE` for `lseek`. Pipes keep the current blocking read/write.
* The process fd table becomes `Vec<Option<FileDescriptor>>` with
  `FileDescriptor { file: Arc<dyn File>, cloexec: bool }`. `dup`/`dup2` share
  the file (and therefore its offset) but clear `cloexec` on the new descriptor,
  as Linux does. `pipe` creates two descriptors with `cloexec = false`.
* `exec` closes the descriptors whose `cloexec` is set, after the new image has
  been installed; a failed exec changes nothing.

`unlinkat`'s flags are `AT_REMOVEDIR` = 0x200 (Linux); `rmdir(path)` is
`unlink(path, AT_REMOVEDIR)` at the libc layer. `creat(path, mode)` is the libc
wrapper `open(path, O_CREAT|O_WRONLY|O_TRUNC, mode)`; there is no separate
syscall number (Linux removed it). `open`'s `mode` is the permission bits a
file created with `O_CREAT` gets, masked by umask (M2.3). The five fs calls M2.3
adds (`mknod` 33, `access` 48, `chmod` 53, `chown` 54, `umask` 166) are listed
with their errors in `docs/perm.md` §7; device dispatch is M3.1. Since M2.3 every
path-taking call in the table can also return `EACCES`, and `open` of a special
file returns `ENXIO` (`docs/perm.md` §6).

The `dirfd`/`AT_FDCWD` arguments of the Linux calls these numbers belong to are
implicit: `path` is resolved against the process cwd, exactly like `chdir`.
`exec` and `spawn` resolve their path through the same walker (cwd-relative).
`exec`/`spawn` of a non-regular file is `EACCES` since M2.3, as Linux does
(`docs/perm.md` §6). `envp`, `#!` scripts and the loader itself are specified in
`docs/elf.md` §4/§5; the two-argument `exec` wrapper passes `envp = NULL`.

## 7. Linux open flags and open semantics

`OpenFlags` takes the Linux values: `O_RDONLY` 0, `O_WRONLY` 1, `O_RDWR` 2
(`O_ACCMODE` 3), `O_CREAT` 0x40, `O_EXCL` 0x80, `O_TRUNC` 0x200, `O_APPEND`
0x400, `O_DIRECTORY` 0x10000, `O_CLOEXEC` 0x80000. Any other bit is `EINVAL`.

* `O_CREAT` creates a regular file in the parent; `O_EXCL` with `O_CREAT` on an
  existing path is `EEXIST`; `O_CREAT` on a directory is `EISDIR`.
* `O_TRUNC` empties an existing regular file (`EISDIR` on a directory).
* `O_APPEND` writes at the end of the file whatever the offset is.
* `O_DIRECTORY` fails with `ENOTDIR` when the target is not a directory.
* A directory opens only with `O_RDONLY` (and no `O_TRUNC`); anything else is
  `EISDIR`. Its fd is read with `getdents64`; `read` on it is `EISDIR`, and
  `write` on that read-only descriptor is `EBADF`, which is also what Linux
  returns.
* Missing path with `O_CREAT|O_DIRECTORY` is `ENOTDIR`: linur never creates a
  regular file for a directory open. Linux returns `EINVAL` for that combination.
* Missing path without `O_CREAT` is `ENOENT`.
* **Behaviour change**: `O_CREAT` no longer implies truncation. Callers that
  meant "create or replace" add `O_TRUNC` (the shell redirection does).

## 9. `getdents64`

Entries use the Linux `linux_dirent64` layout: `d_ino: u64`, `d_off: i64`,
`d_reclen: u16`, `d_type: u8`, then the NUL-terminated name; the record length is
the header (19 bytes) plus the name, rounded up to 8. `d_off` is the byte offset
of the *next* entry, so a caller can continue from it. `d_type` is `DT_DIR` 4,
`DT_REG` 8. Iteration starts at the file offset and stops after the entries that
fit; a full buffer returns what fit, an exhausted directory returns 0. The
directory's file offset advances with the records returned. `.` and `..` are
listed like any other entry.

## 10. cwd

Every process has a `cwd: Arc<Dentry>`: the root at boot, inherited on `fork`,
unchanged by `exec`. `chdir` resolves the path (against the current cwd) and
requires a directory (`ENOTDIR`). `getcwd(buf, size)` writes the absolute path
plus a NUL and returns the length including the NUL; a buffer that is too small
is `ERANGE`.

## 11. Errors

New errno values (kernel and user list must match): `EEXIST` −17, `ENOTDIR` −20,
`EISDIR` −21, `ESPIPE` −29, `ENOTEMPTY` −39, `ERANGE` −34. `ENAMETOOLONG` −36
and `EINVAL` −22 already exist. `VfsError` maps: NotFound→`ENOENT`,
Exists→`EEXIST`, NotEmpty→`ENOTEMPTY`, NotDirectory→`ENOTDIR`,
IsDirectory→`EISDIR`, InvalidName→`EINVAL` (a name that exceeds the limits is
`ENAMETOOLONG`, decided in the kernel before the disk call). M2.3 adds `EPERM` −1,
`ENXIO` −6 and `EACCES` −13, decided in the kernel (`docs/perm.md` §10).

## 13. Deliberately not in the VFS yet

Permissions, modes, device nodes and the mount table left this section in M2.3
(`docs/perm.md`), and the buffer cache and the block driver in M2.4
(`docs/block.md`): the checks, `chmod`/`chown`/`umask`/`access`/`mknod`, the
one-filesystem mount table in `os/src/fs/mount.rs`, the `/dev` skeleton, the
hash-queue cache with delayed write and the own virtio-blk driver are all in. Still
out: `mount()`/`umount()` and per-inode superblock back-pointers (M6.1), a dentry
cache (not scheduled), symlinks (DEFER). The `Dentry` shape did not change; the
walker still never crosses a mount point.

buffer. `AT_REMOVEDIR` 0x200, `S_IFREG`/`S_IFDIR`/`S_IFCHR`/`S_IFBLK`/`S_IFIFO`,
`DT_DIR` 4, `DT_REG` 8, the `*_OK` access modes and `makedev` are exported.
